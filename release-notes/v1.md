**<변경점>**

**1. 다른 맵(특히 연구소)에서 쓰레기 메모리가 많이 생기던 것**
- 등대 리워크를 깔아 두면 등대가 아닌 맵에서도 1분에 20~58MB씩 쓰레기 메모리가 생겼습니다(연구소). 쌓인 쓰레기를 치울 때(GC) 게임이 끊기고, RAM 클리너 목록에 이 모드가 나오던 이유입니다.
- 원인: 면광원(AreaLight)마다 매 프레임 "등대 장면인가?"를 확인하면서 장면 이름 글자를 매번 새로 만들었습니다(연구소는 면광원 약 140개, 1분에 70~80만 번).
- 이제: 등대 장면을 불러오지 않은 판에서는 아무것도 확인하지 않고 바로 넘어가고, 한 번 "아님"으로 본 장면은 기억합니다.
- 확인: 개발자 게임 연구소 판 측정 — 이 부분이 만드는 쓰레기 1분에 20.5MB → 0.1MB.

**2. db 파일을 고치면 게임이 안 켜지던 것**
- `SPT_Runtime/user/mods/ManimalLighthouse/db` 안의 json(전리품·위치·아이템)을 하나라도 고치면 서버가 모드를 멈춰 게임 접속이 막혔습니다.
- 원인: 서버가 db 파일마다 원본 지문(SHA-256)을 맞춰 보고 하나라도 다르면 멈췄습니다. 모드가 db 파일을 다시 쓰는 것은 아닙니다.
- 이제: 고친 json은 서버 창에 경고 한 줄만 띄우고 그대로 씁니다. 파일이 없거나 json이 아닌 파일이 바뀐 경우는 전처럼 멈춥니다. 고친 내용은 서버를 다시 켜야 적용됩니다.
- 확인: 서버와 게임이 메인 메뉴까지 오류 없이 켜지는 것 확인. db를 고친 상태로는 아직 실험하지 않았습니다.

**<Changes (English)>**

**1. Lots of garbage memory on other maps (Labs especially)**
- With the Lighthouse Rework installed, maps other than Lighthouse produced 20-58 MB of garbage memory a minute (Labs). Collecting it (GC) causes stutter, and it is why the RAM cleaner listed this mod.
- Cause: every area light asked "is this a Lighthouse scene?" every frame and built a new scene-name string each time (Labs: ~140 area lights, 700-800k calls a minute).
- Now: when no Lighthouse scene is loaded the check returns right away, and a scene found foreign once is remembered.
- Checked: measured on a Labs raid on the dev PC - garbage from this part 20.5 MB → 0.1 MB a minute.

**2. Editing a db file stopped the game from starting**
- Editing any json under `SPT_Runtime/user/mods/ManimalLighthouse/db` (loot, locations, items) made the server stop the mod and the game could not connect.
- Cause: the server compared every db file with its shipped SHA-256 and stopped on any difference. The mod does not rewrite db files.
- Now: an edited json only prints one warning in the server window and is used as is. A missing file or a changed non-json file still stops it like before. Restart the server for edits to apply.
- Checked: server and game start to the main menu without errors. Not yet tried with an edited db file.

- Also includes the original author's **buoy flicker fix** (`76daf31`) that landed in the repository after the sp-mod 1.0.7 release (not checked separately in game).

**Known issues**
- If anything is off, extract the original mod again to go back.
- Please don't contact the original author about this build.

**Install / update**
- **Install the original mod first** (this zip has no map bundles): https://sp-mod.com/mod/3022/manimals-10-lighthouse-rework-backport
- Then extract `Manimal-Lighthouse-1.0.7-zzap-v1.zip` into your SPT folder and overwrite. Settings are kept.

Hi everyone,

I'd like to share a few thoughts and important warnings regarding the process of porting mods from version 4.0 to 4.1.

Following the recent "ECOT" mod incident, I've had a lot of time to reflect on my actions.
I’m not here to lecture anyone—I’m writing this simply in the hope that you’ll keep these points in mind.


**1. I am not a professional programmer; I am mostly a "vibe coder" who relies heavily on AI.**

By that, I mean I’m not someone who spends days designing and painstakingly crafting mods by hand from scratch.
At the same time, having tinkered with simple mod edits back in the TS/JS (SPT 2.3.1) days, I know firsthand how much time, effort, and care goes into this process.
Therefore, even if a mod is covered under an MIT License, if the original author requests that I delete the source code and stop distribution, I will willingly comply.


**2. Please DO NOT re-distribute or re-upload these modified mods to 3rd/4th party places.**

Even if my ported version has some fixes or improvements, please do not treat it as a long-term solution. Unlike official releases on "THE FORGE," I do not perform thorough debugging or full security scans.
Furthermore, imagine how disruptive it would be if someone mistook my ported build for an "official release" and pestered the original author about bugs in my version. It would be terrible.
Moving forward, I intend to approach any porting work with the utmost respect for original modders.
If I had spent days pouring my heart into making a mod, only to have someone take my code and modify it however they pleased, I wouldn't feel good about it either.
Therefore, when writing README.md files on GitHub, I will always credit the original creators, and if it's not a mod I built from scratch, I will fully respect the original modder's decisions and opinions.


**3. Please respect the original creators.**

If people ignore warning 2. and act as if my port is the "real deal," I would feel immense guilt.
Please do not do that. As the saying goes, "When in Rome, do as the Romans do"—and showing proper respect and courtesy is essential.
Instead, please visit the original creators' comment sections on The Forge to leave warm words of appreciation, encouragement, or even buy them a coffee/leave a tip if you can


**Thank you for reading this long post.**
